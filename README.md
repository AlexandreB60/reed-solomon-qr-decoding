# QR code generation and decoding of corrupted codes

Year-long research project (TIPE) carried out by a team of three between September 2024 and June 2025, in MPSI-MP\* preparatory classes at Lycée Sainte-Geneviève (France).

A QR code is generated from a message, encoded with a Reed-Solomon code over GF(256), corrupted on several bytes, and the original message is then recovered by decoding through the finite-field Fourier transform.

Source code, identifiers and comments are in French.

## How it works

### Reed-Solomon codes

A QR code protects its data with a Reed-Solomon code over GF(256), a special case of BCH codes.
Codewords are the multiples of a generator polynomial g in $GF(256)[X]/(X^{255}-1)$.
At correction level H, g has degree 17, which allows up to 8 erroneous bytes to be corrected. 

### Decoding through the Fourier transform

Let $\nu$ be the number of errors, at positions $i_1, \dots, i_\nu$ and with values $e_1, \dots, e_\nu$. The syndrome of index j is the j-th component of the Fourier transform of the received word:

$$S_j =\sum_{l=1}^{\nu} e_l \, X_l^{\, j}, \qquad X_l = \alpha^{i_l}$$

These components depend only on the error, not on the codeword that was sent: this is what makes it possible to locate the errors without knowing the original message. The error-locator polynomial $\sigma$ is obtained by solving a linear system, the Fourier transform of the error is then extended through the recurrence associated with $\sigma$, and the inverse transform is applied.

When the actual number of errors is strictly smaller than `t`, the matrix of the system is singular. The system is therefore solved by reduction to row echelon form, which accepts that case and returns a particular solution by setting the free unknowns to zero.

### Arithmetic through logarithm tables

GF(256)\* is cyclic of order 255, generated by $\alpha = X$. Every non-zero element is therefore written as $\alpha^i$ in a unique way, and $\alpha^i \cdot \alpha^j = \alpha ^{((i+j) \bmod 255)}$: a multiplication becomes an addition of integers. Two tables of 255 entries - powers and discrete logarithms - replace the polynomial multiplication followed by a modular reduction. The measured speed-up is about a factor of 30.

### Why the radix-2 FFT does not apply here

The `fft_radix2.py` module implements a classical Cooley-Tukey algorithm, validated over GF(17).
It is not used by the decoder, and cannot be: radix-2 requires a primitive $2^k$-th root of unity, whereas GF(256)\* has order 255, which is odd, so none of its elements has even order.

## Known limitations

- The `t` parameter of the decoder must be an upper bound on the actual number of errors, and must not exceed the capacity of the code. Beyond that, decoding returns an incorrect word without reporting it.
- The number of errors is assumed to be known and passed as a parameter. Determining it from the syndromes alone would require an additional algorithm, which is not implemented here. 
- The transforms run in $O(n^2)$: the powers of the root are precomputed, but the algorithm remains the direct definition.

## Tests

`test.py` checks the round trip of the transforms, the agreement between the radix-2 FFT and the DFT over GF(17), and the decoding of 0 to 8 errors at random positions - both with `t` equal to the number of errors, and with `t` as an upper bound.
